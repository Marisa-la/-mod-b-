# 魔理沙 MOD · Stronghold-Protocol 0.3.0

用户已完成本机游玩验收。本版将魔理沙 MOD 管理器和玩法迁入原版 0.3.0 的原生插件系统，保留四名干员、罗德岛、鲲、驻防、皮肤与形态、自选候选和单场回放。本页与适配代码使用 AI 辅助整理。

## 累计修补包：更新已安装的完整包（2026-10-17）

本次只发布一个增量修补包 `Stronghold-Protocol-0.3.0-marisa-hotfix1.zip`，源码同步到仓库。不重新打包完整包、兼容替换包或单独插件包。

适用基准为[此前发布的 Marisa 0.3.0 完整包](https://github.com/Ruyl114514/marisa-s-mod/releases/tag/marisa-0.3.0-20261016)中的 `Stronghold-Protocol-0.3.0-marisa-full.zip`。无论尚未安装修补，还是已安装 2026-10-16 的旧修补包 1，都可直接覆盖本累计包，无需先卸载或补装旧补丁。修补包只含相对这两种状态发生变化的必要文件及说明，不能单独运行，也不能直接覆盖原版游戏、0.2.x 旧 MOD 或其他改版。

1. 停止正在运行的游戏服务，备份原安装目录。
2. 解压修补包，把里面 `Stronghold-Protocol` 文件夹中的内容合并到原游戏目录，确认覆盖同名文件。应与原有 `package.json`、`server`、`plugins` 文件夹处于同一层，不要多套一层目录。
3. 使用原来的启动脚本重新启动，浏览器按 `Ctrl+F5`，创建新对局。旧对局仍使用开局时固定的插件内容。

本累计包包含模组启动器的联机修复：移除固定的 `127.0.0.1` 监听，恢复与原版相同的默认监听；保留上次罗德岛溢出治疗攻击加成重复放大、上限同帧回落及鲲图标映射修复。鲲的吞噬击倒计数、复活和起飞规则与原作者 0.2.4 一致；起飞标志继续覆盖技能、天赋和鲲带来的所有干员起飞状态。完整包内既有依赖和游戏素材不重复包含在修补包中。

## 安装和启动

- **完整包**：解压到新目录，包含程序、生产依赖、前端库和本机已准备的游戏素材；需要 Node.js 22 或更新版本。Windows 双击 `scripts/start-marisa.cmd`，其他系统运行 `SP_PLUGIN_SCRIPTS=sandbox node scripts/launch.mjs --no-setup`。
- **兼容替换包**：只用于未修改的原版 0.3.0。停止服务并备份后，将包内 `Stronghold-Protocol/` 的内容合并覆盖原安装，保留原有素材。包含兼容程序、依赖、插件及追加素材；不是跨版本自动更新包，不适用于旧 MOD 或其他游戏版本。
- **单独插件包**：`marisa-0.3.0.zip` 使用原版插件格式，安装到 `plugins/marisa/`。必须先安装本版兼容补丁；单独放进未修改原版 0.3.0 不能保留全部功能。完整包和兼容替换包已经安装此插件，无需重复安装。

再次双击启动脚本会复用正在运行的游戏并打开页面；关闭网页不会停止服务。在首次启动的服务窗口按 Ctrl+C 可停止。不要同时启动多个服务争用 3000 端口。

模组启动脚本与原版沿用相同的监听地址默认值：未设置 `HOST` 时监听 `::`，同时接收 IPv4/IPv6；系统未启用 IPv6 时自动回退到 `0.0.0.0`。朋友使用主机的局域网或 VPN 地址访问，主机自己仍可打开 `http://localhost:3000`。不再固定 `127.0.0.1`，后者只接受本机访问。需要仅本机运行时可显式加 `--host 127.0.0.1`。修改监听设置后必须先停止旧服务器再启动；重复双击不会改变已运行进程的监听地址。

## 在哪里配置 MOD

1. 创建房间，点击房间顶部的“插件”标签。
2. 开启“魔理沙追加 MOD”，在其管理器中展开分类。
3. 点击“应用设置”，等待插件内容就绪后开始对局。

管理器保留已有干员原版/MOD 切换、追加干员启停和商店/V、VI 阶自选路线、罗德岛及原版盟约新增成员、鲲策略等配置。结城理、医疗阿米娅进入自选后不再进普通商店，同一追加角色跨 V/VI 阶只能编入一个位置。明确的成员选择优先于干员模式；盟约总开关关闭时成员不生效。干员装备模组偏好保持独立。加入者、观战者和重连者使用房主的原生内容配置与哈希。

## 兼容补丁范围

原版 0.3.0 的接口不足以直接表达全部旧 MOD。本版补充新增盟约命名空间、声明式配置合成、脚本效果及召唤物分发、完整数据视图、整备期叠层来源和范围、自选互斥、形态/皮肤与起飞显示。脚本仍使用原版内容哈希、锁验证、SES 沙箱和执行预算。

脚本启动超时、进程异常或缺失报告不再永久缓存为“不兼容”，相同设置可重新应用；显式脚本错误仍被拒绝和缓存，超时进程仍被终止。

## 开发与验证

2026-10-16 游玩问题跟进：罗德岛光环的溢出治疗按 1:1 转成实际攻击力，最多增加不含该光环加成的自身攻击力的 100%；修正技能攻击力百分比将这份加成再次放大的旧版问题。技能自然结束、较晚加入的临时加成到期时，同一帧的普攻和显示也会按新上限计算，不再迟一帧下降。连续 2 秒没有溢出仍会移除加成。鲲补齐插件策略编号到原图的素材映射，恢复原图。

已对照[原作者 0.2.4 发布包](https://github.com/Marisa-la/marisa-s-mod/releases/tag/v0.2.4)：鲲函数与迁移源逐字一致，保留每场第三次吞噬实际击倒后免费重新部署前三名被击倒干员、最后一次击倒的来源起飞的逻辑；存活的吞噬目标不计数。链条仅穿过阿戈尔成员，遇到非成员时会吞噬该目标并停止，目标朝向不会继续传递。高层阿戈尔提高生命值，可能导致三次击倒不足。截图所述折线站位在 0 层时击倒并复活三人、歌蕾蒂娅起飞；154 层时只击倒两人，不触发鲲。起飞标志按通用 `UF.LIFTOFF` 显示，覆盖技能、天赋和鲲的起飞，落地时消失，与策略选择无关。

可读脚本来源与生成入口在 `mods/marisa-native/`，可安装产物在其 `bundle/marisa/`。安装插件：将该文件夹复制到 `plugins/marisa/`。重建需先在 `mods/marisa-native/` 安装其开发依赖，再运行构建脚本；修改文件后运行 `node tools/plugin.mjs check marisa --strict`、`node tools/plugin.mjs test marisa` 和 `node tools/plugin.mjs pack marisa --zip`。正式打包入口为 `node tools/package-marisa.mjs`。

本次累计修补使用独立入口 `node tools/package-marisa-hotfix.mjs --force --previous 旧修补包路径`。先将原完整 ZIP 放入 `.cache/dist/Stronghold-Protocol-0.3.0-marisa-full.zip`，并保留旧修补包 1（SHA-256：`44058c31e6d0dfadc255523485d0fb5f675bf5f3f2a3a254a574ef0dca69e508`）供第二基准验证。工具校验两个基准包，只把与任一基准不同的必要文件加入一个差异 ZIP；分别验证原完整包和已安装旧修补包两种状态下的覆盖、安装清单、插件回归、局域网/VPN HTTP、WebSocket 和 sandbox 房间加入，最后比较两份安装的全部发布文件一致。网络验证需本机有可用的局域网或 VPN 接口；此入口不生成新的完整包、兼容替换包或单独插件包。
