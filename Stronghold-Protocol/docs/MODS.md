# 魔理沙追加 MOD · 0.2.6

这是基于 Stronghold-Protocol 0.2.6 的可维护源码分支。原版与 MOD 房间可同时在同一服务器运行。
默认使用原版规则。在大厅打开 **MOD 管理器**，勾选 **启用魔理沙追加 MOD** 后，可分别配置已有干员改动、追加干员、追加盟约、现有盟约追加干员和追加策略。
已有干员区只列出实际受 MOD 改动的原版干员；结城理和医疗阿米娅可独立启用并选择商店或自选候选；现有盟约可逐个管理新增成员。
房间创建后整份配置固定；加入者、观战者与断线重连者跟随房主的配置。改变配置需要创建新房间。
浏览器记住创建者的选择；这个偏好不能修改已加入房间的规则。

## 安装与运行

使用 Node.js 22 或 24，在工程目录执行：

```sh
npm ci
npm run setup
npm start
```

打开 http://localhost:3000，在大厅选择是否启用 MOD。生成后的原版和 MOD 数据随源码提供，启动无需重新生成。
素材在 `public/assets/` 和 `public/fonts/`，由 setup 下载，不提交到 Git。皮肤缺少立绘时不会提供选项；缺少皮肤模型时保留默认模型。

也可执行 `node tools/import-mod-assets.mjs <旧替换包中的 Stronghold-Protocol 目录>` 导入本机已有素材。
工具只复制素材，并过滤本地清单中实际不存在的文件，不安装旧代码或更新标记。

单人测试资金模式（仅 MOD 房间、人类玩家生效）：

```powershell
$env:SP_DEV_FUNDS = '9999'
$env:PORT = '3001'
npm start
```

多人房间、机器人、原版房间均不补充测试资金。收入通过现有结算与审计通道入账。

## 内容与来源

- MOD 为结城理、予愿安洁莉娜、凯尔希·思衡托、医疗阿米娅各添加普通与精锐商店棋子。予愿和凯尔希在 0.2.6 已有 V、VI 阶候选，归入“已有干员”；切回原版会移除 MOD 商店棋子并保留原版候选、技能、装备模组选项与召唤物。结城理与医疗阿米娅是本工程新追加的干员，各有独立启用开关。
- 结城理和医疗阿米娅默认从商店获取，也可各自改为 V、VI 阶自选候选；改为自选后不进入普通商店，是否编入由玩家决定。同一角色不能跨两个阶级重复编入。其 MOD 原型使用 MOD 技能和对应自选位置召唤物，不自动携带装备模组，也不改写浏览器已保存的装备模组偏好。
- “已有干员”只列受 MOD 改动的原版角色，包括华法琳、凯尔希、Mon3tr、电弧、可露希尔、机械师、予愿安洁莉娜和凯尔希·思衡托。逐名选择原版会恢复原版记录；予愿和凯尔希的 MOD 新增商店棋子也会移除。
- **追加盟约**只显示新盟约或规则本身改变的盟约；当前只有罗德岛。盟约下列出华法琳、凯尔希·思衡托、医疗阿米娅、凯尔希、Mon3tr、电弧、可露希尔和机械师，停用的追加干员隐藏。成员开关显式选择后，优先于干员的原版 / MOD 模式：取消凯尔希成员资格后，即便使用 MOD 模式也不会有罗德岛；明确开启则可为原版模式的候选添加罗德岛，只改变盟约归属。未操作的成员沿用干员模式；关闭整个盟约仍会暂停所有成员。
- **现有盟约追加干员**按启用的 MOD 干员动态列出新增成员：结城理可加入拉特兰、精准、不屈；予愿安洁莉娜可加入叙拉古、迅捷、奇迹；医疗阿米娅可加入远见；凯尔希·思衡托可加入协防干员。逐项取消只移除该 MOD 商店记录的新增归属；干员停用后，其盟约选项隐藏。若没有其他归属，干员使用协防干员回退；明确取消协防干员成员时不触发回退。
- 当前安装的 `emptyShip` 是原版“协防干员”，不是“空想”；管理器不会创建当前数据中不存在的“空想”。
- 鲲策略可独立关闭；关闭后不加载鲲策略及其效果，原版阿戈尔干员仍按原有玩法运行。
- 罗德岛盟约：保留原包的成员、整备期与战斗期镜像叠层、其他已激活盟约最高层上限、四人在场效率变化、人数贡献、治疗及弱点伤害效果。
- 化鲲为鹏：三次有效吞噬击倒触发一次复活，让最后一次吞噬的来源起飞并获得对空攻击、阻挡。
- 结城理「见证荣光」皮肤、本地外观偏好、形态动画与特效。

代码来源为 [Marisa-la 的替换包](https://github.com/Marisa-la/marisa-s-mod)，本地参考包的 README 标注上游基线 0.2.4。
替换包保留了 JavaScript，但缺少它引用的设计文档、构建工具与测试；本分支重建了这些维护入口。
保留原作者与上游的 GPL-3.0-or-later 说明和非商业限制。游戏素材属于原权利人。

干员属性、潜能、技能、天赋和实际召唤物数据由上游构建器从官方数据表推导。
医疗阿米娅读取 `char_patch_table.json`。自定义商店配置、盟约、驻防、策略、展示用人格面具和皮肤登记在
`mods/marisa/content.json`，不手工修改生成 JSON。

明确的自定义/推断点：原包的商店阶级、价格、盟约归属与驻防是 MOD 设计；凯尔希·思衡托 S3 的可选开放沿用原包。两名真正追加干员的 MOD 自选原型使用现有 V、VI 阶自选位置与 MOD 默认技能，同一角色仅能选择一个位置；未启用 MOD 改动的原版已持有候选继续沿用其技能和装备模组选择规则，不改变已保存的干员装备模组偏好。
鲲的最后击倒来源起飞、达到三次仅触发一次、显示型人格面具不占独立部署格等推断保留代码中的 `[ASSUMED]` 标记。

## 与旧替换包的差异

- 保留 0.2.6 的网络压缩、素材哈希缓存、场景和其他上游修复。
- 干员属性、技能和潜能由官方数据构建，不沿用旧包快照作为数值来源。
- 普通/精锐记录补齐自备信息、召唤物变体与潜能数据；显示型面具标明来源，不参与官方属性推导。
- 予愿 S3 的范围在 MOD 中跟随冲刺位置；原版自选干员继续使用原版 kit。
- 罗德岛保留旧包已有的治疗反馈递归保护及溢出攻击力上限修复，并加入回归检查。
- 新增房间配置隔离与内容校验；子选项组合生成独立玩法数据与内容哈希。切换房间清除旧数据，内容不匹配时浏览器拒绝模拟，由服务器按现有机制接管。旧客户端只发送 MOD 总开关时继续使用完整 MOD 默认设置。
- 测试资金额外要求当前房间启用 MOD。旧包的 UPDATE.json、MANIFEST.json 与 node_modules 不覆盖新版。

## 重建、测试与同步

```sh
npm run build-data
npm run build:mod
node tools/build-i18n.mjs --data data/mods/marisa --out data/mods/marisa/i18n/en.json
node --test test/mod/*.test.js
npm run ci
npm run golden
node tools/i18n.mjs check --all --strict
node tools/package-mod.mjs
```

日语、韩语和繁体中文数据重建使用 `--lang ja|ko|zh-TW` 和对应输出文件。缺少官方译文的追加文本回退中文。
官方数据已缓存后可为构建命令加 `--offline`。同一输入必须生成相同输出。

未来同步：先合入新的上游版本，保留两个 profile；比较原版数据和 golden，重新生成 MOD 数据，再运行 MOD 测试与完整验证。
自定义干员 kit 位于现有 kits 目录；两个原版自选 kit 与对应 MOD kit 分开维护，避免关闭 MOD 时改变原版玩法。
升级时检查商店、联防、首领、召唤物、素材哈希、所有语言和内容标识。原版 golden 不包含 MOD 场景；MOD 场景由独立测试覆盖。

`node --test test/mod/browser.e2e.test.js`。覆盖管理器、房间配置、内容校验、跨引擎结果、皮肤持久化与四名干员的实际模型。

本机验证可设置 `SP_TEST_CONCURRENCY=2` 再执行 `npm run ci`，限制测试进程数，不减少任何测试。
限流测试使用注入的固定时钟验证突发与补充，避免机器负载改变发送时长；Windows 目录链接测试使用 junction。
